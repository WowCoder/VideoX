# 当前边界与验收范围

[返回 README](../README.md) · [架构](architecture.md)

OpenVMA 提供可检查的应用工作流，以下边界帮助部署者确定需要补充的服务和验证。

## 创作与 AI

- 当前没有多人实时协作、协作者邀请或共享编辑权限工作流。项目以当前用户的工作区为中心。
- 素材匹配产生候选，用户选择后才能用于主成片；它不承诺召回质量，也不会自动对缺失镜头付费生成。
- 一个项目使用唯一脚本与主成片配置。修订记录和素材版本用于追踪变化，不代表多个独立初剪项目。
- 文本、视觉、图片和视频 Provider 支持范围不同；TTS 和草图动效当前只有 DashScope。没有任意模型服务的通用自动兼容层。
- 云端模型依赖部署者的账号、模型权限、网络与额度，可能收费；本地模型需下载权重并消耗硬件资源。仓库不提供统一速度、质量或成本基准。
- 生成结果会按版本保护保存，但仍需要用户判断内容是否合适。引用 URL 校验不能证明模型摘要与每项事实准确。
- 联网选题发现依赖可抓取来源。搜索失败、来源封禁、动态页面或结构变化会影响结果；监测区分基线/无变化/结构变化，不把抓取当成内容更新。

## 任务与媒体

- 提交结果未知时不盲目重提付费视频；可能需要查供应商记录或人工处理。已有 task id 的恢复依赖供应商保留任务和产物。
- 排队容量与在途并发是保护措施，不能消除供应商限流、超时、媒体下载失败或部署资源不足。
- 主成片编排成功不等于镜头已补齐或导出成功。导出以真实 FFmpeg 完成及媒体持久化为准。
- 主工作区目前提供 MP4 导出；后端其他格式实现不表示所有格式都有同样的前端入口或兼容性验收。
- 浏览器预览、源媒体编解码器和最终 FFmpeg 成片可能有显示差异。正式交付前应播放实际导出文件，核对字幕、音轨、时长和画幅。
- 默认上传上限为 1 GiB，生产代理必须做实际链路验收；大文件性能不能只从配置推断。

## 账号与部署

前端面向桌面浏览器，使用 Tailwind CSS 4；需要 Safari 16.4+、Chrome 111+ 或 Firefox 128+。手机可以访问项目展示页，完整编辑器的操作布局以桌面为主。

邮箱注册/登录不需要短信或微信账号；手机号和微信登录需要部署者接入自己的服务。邮箱密码注册不等于已完成邮箱所有权验证或密码找回服务，应按自己的公开运营要求评估身份能力。

会员、账单、订单和发票申请保存在业务数据库中，但正式收款、发票开具和商户合规需要外部服务；仓库代码本身不能替代这些运营步骤。

运营后台是独立入口和管理员账号，并要求 TOTP。生产模板仍需部署者设置密钥、域名、证书、受保护网关、备份、监控和恢复演练。根目录开发 Compose 不用于公网生产。

GitHub Pages 只提供静态项目介绍，不是托管视频创作服务；预计地址不代表已部署。Pages 内容中的概念图不代表真实模型输出或已测性能。

## 验证记录的含义

单元测试、类型检查和构建可以验证相应代码边界，不能代替外部供应商真实推理、全平台媒体兼容性、完整生产负载和灾难恢复测试。提交验收记录时说明环境、输入、命令与结果；没有记录的功能不宣称已经获得端到端验证。

代码的 MIT 许可不自动覆盖模型权重、供应商服务和用户上传素材。公开演示应只使用具有再分发权限的材料，见 [第三方说明](../THIRD_PARTY_NOTICES.md)。
